# M19：只读数据与因果回放

M19 是给个人使用的“数据 → 因果回放 → 最新纸上目标”运行层。它不创造新的指标、阈值或仓位，也不修改 M18、M16、v12.2 的原文件。

## 版本关系

| 名称 | 当前值 | 含义 |
|---|---|---|
| 运行版本 | `m19-readonly-data-replay/v1` | 本次数据获取和决策包装层 |
| 回放标签 | `v12.2-causal-walk-forward/v1` | 因果 Walk-Forward 计算外壳 |
| 实际策略源 | `v10_preserve_shock_recovery` | 冻结的 v10 候选策略合同 |
| 产品运行边界 | `paper_only=true`、`execution_allowed=false` | 只给纸上目标，不接券商、不下单 |

这里的 v12.2 不是一套重新调过参数的策略。策略本身仍然由 v10 合同和 M02–M07 现有服务决定，M19 只负责把截至某个收盘日的数据送入它。

## 两种数据模式

### Massive 模式

`configs/m19/readonly.json` 的 `provider` 为 `massive` 时，M19 只请求五条必要序列：

- QQQ：策略和基准
- BIL：现金代理
- VXX：冲击仓位；缺失时必须失败
- VIX、VIX3M：信号输入，不是可持有资产

API key 只从进程环境中的 `MASSIVE_API_KEY` 读取。它不会进入配置文件、代码、日志、邮件或 Artifact。Massive 权限不足、限流、缺少 VXX/VIX、空响应和异常数据都会 fail-closed。

### local_csv 模式

`local_csv` 是免费的离线历史回放模式，读取配置中已有的三份本地 CSV，并且只保留截至指定日期的数据。它适合验证“每天只看当日以前的数据”，不是 Massive 失败时的自动线上替代源。

运行时会重新生成临时输入 CSV，并在 `provider_manifest.json` 中记录源文件或响应快照的 hash；不会覆盖研究目录里的原始文件。

## 时间和防前视

- `open`、`midday`：只使用最近一个已经完整结束的 NYSE 日线；当天盘中数据不能改变目标仓位。
- `close`：只有纽约时间达到 `16:15` 后才允许把当日收盘当作信号；如果 Action 延迟或尚未收盘，会退回上一个完整交易日。
- `email`：北京时间 08:23 读取最近一次已经完成的美股收盘。
- 信号日收盘产生目标，下一美股交易日才是纸上执行日。

每次运行都会输出 `decision.json`、`provider_manifest.json`、`run_metadata.json`，并在成功时附带原 v12.2 的回放报告和检查文件。盘中结果标记为 `INTRADAY_PROVISIONAL`，不能被误读成确认目标。

## 运行边界

M19/M20 不读取券商账户、不估计实际成交、不创建订单、不转账。它只生成提醒和纸上目标。任何策略规则变化都必须创建新的策略版本和新的回测证据，不能为了让某一年变好而直接改这里的运行配置。
