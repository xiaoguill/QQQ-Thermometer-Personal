# QQQ 温度计：个人使用版边界治理

## 1. 目标

最终目标是一个供本人每天查看和手动执行参考的低频系统：它能够在美股收盘后读取数据，计算已冻结策略的状态，展示温度与证据，给出下一交易日目标权重，并维护纸上组合账本。

它不是券商系统、不是面向公众的网站、不是自动交易机器人，也不需要生产级 SLA、弹性扩容、多用户权限或云端高可用。

## 2. 个人版必须具备的能力

### 必须保留

- 固定策略版本和配置 hash；当前候选以 `v10_preserve_shock_recovery` 作为研究来源，实际默认版本必须在运行时接入后再登记。
- QQQ、VIX/VIX3M 及策略实际需要的 ETF 日线数据。
- 指标预热、信号日期、执行日期、数据更新时间和质量状态。
- 温度、趋势、信号一致度、各项证据和未触发原因。
- 目标权重、当前纸上持仓、净值、回撤、换手和成本。
- 历史回放、逐年结果和 QQQ 基准对照。
- 手动暂停、手动确认、纸上账本和版本回滚。
- 原始数据清单、运行清单、配置、报告和 hash，保证能够重建结果。

### 默认不实现

- 真实订单、券商 API、自动再平衡、转账、融资、保证金、做空和期权。
- 公网访问、多人账户、登录体系、云端数据库、容灾、自动扩缩容和高可用。
- 机器学习自动选参、遗传算法、在线学习或根据最近收益自动切换策略。
- 盘中频繁交易；盘中只允许显示 `PROVISIONAL` 观察，不产生最终目标权重。
- 由前端按钮修改策略参数、覆盖策略权重或改变历史账本。
- 完整的 FastAPI/React 产品化拆分。未来目录可以保留，但未获批准前不生成对应业务代码。

## 3. 建议的个人版最小架构

```text
数据适配器/本地缓存
        ↓
指标与 v10 状态纯函数
        ↓
目标权重与 paper ledger
        ↓
Streamlit 本地页面
```

推荐保留和优先实现：

```text
research/qqq_drawdown_strategy/  研究和审计
src/thermometer/                 纯状态与权重逻辑
src/web/                         当前 Streamlit 页面
tests/unit/                      纯函数测试
tests/replay/                    历史回放与防前视测试
docs/                            规则、报告和操作手册
configs/                         非敏感冻结配置
```

`src/api/`、`frontend/`、`src/jobs/`、`src/observability/`、`tests/integration/`、`tests/contract/` 和 `tests/frontend/` 目前都属于延期能力。个人版若需要持久化，优先采用本地 SQLite/CSV 适配，不做生产级数据库服务。

## 4. 日常运行边界

### 收盘后流程

1. 手动或 Windows 任务计划程序启动一次日线刷新。
2. 检查行情是否更新、是否缺失、是否出现异常价格差异。
3. 计算截至收盘的指标和状态；只有质量通过才标记 `CONFIRMED`。
4. 生成下一交易日目标权重，不在当日收盘价上假设已经成交。
5. 写入纸上账本和运行清单。
6. 用户查看证据、目标权重和异常；如不确认，则保持暂停，不自动执行。

个人版不要求无人值守。任何数据异常、策略版本不一致或结果无法重建时，默认“不发布确认信号”。

### 风险约束

- 目标权重必须合计 100%，并通过非负、资产集合、warmup 和执行日检查。
- QLD、SVXY、VXX 等特殊风险资产的上限必须在冻结配置中写明，不能由页面临时改变。
- 不允许因为“当前行情看起来危险”而在页面直接手工改写策略输出；如果用户不想跟随，可以记录为独立的 `manual_skip` 事件。
- `manual_skip` 不修改策略状态、不修改回测、不伪装成策略成交。

## 5. 数据边界

- 个人版允许一个主数据源加一个抽样复核源，不要求生产级多源自动切换。
- 数据必须保存来源、抓取时间、交易日、价格口径和 hash。
- 近期数据过期、缺失或跨源差异超过预先定义的检查范围时，状态为 `NEEDS_REVIEW`。
- 不能用未来数据填充历史指标，不能用盘中未确认值覆盖收盘确认值。
- API key、SMTP 密码、账户截图和私人聊天记录放在仓库外；`email_config.json` 只能作为本机私密配置，不能提交。

## 6. 个人版验证门槛

不追求生产级认证，但必须通过以下实用门槛：

- 单元测试和历史回放测试通过；
- 2008、2019、2020、2022 等代表阶段没有前视或信号/执行日错位；
- 目标权重、换手、成本和净值可以逐日重建；
- 5/10/25 bps 成本压力测试结果可查看；
- 至少连续 20 个交易日纸上观察后再作为个人日常参考；
- 每次运行有版本、数据清单、时间戳和结果文件；
- 一次运行失败不会覆盖上一次已确认结果。

## 7. 最小备份与恢复

个人版采用“Git 保存代码与规则，仓库外保存生成物”的方式：

```text
代码/文档/测试：D:\Backup\Documents\量化回测\FinRL-Trading
回测与行情生成物：D:\Backup\Documents\量化回测\_quant_artifacts\FinRL-Trading\<run_id>\
私密配置：用户目录或 Windows Credential Manager
```

每个 artifact 目录至少包含 `manifest.json`、配置 hash、Git commit、数据 hash、运行命令、报告和关键 CSV。生成物不需要全部进入 Git，但必须能由清单定位和验证。

## 8. 何时需要重新审批

以下变化必须另开任务并产生新版本：策略规则、阈值、资产集合、资产上限、执行时点、数据源、价格口径、成本假设、运行频率、真实交易、公开访问或任何自动化订单动作。

页面颜色、布局、解释文案和本地报告格式可以在不改变策略语义的前提下独立修改。
