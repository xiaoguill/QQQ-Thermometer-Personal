# M16 回放与数据质量报告

## 结论

M16 的盘中观察只允许进入 `PROVISIONAL`，质量不满足条件时 fail-closed；它不能创建或覆盖 M04–M07 的 `CONFIRMED` 状态、目标权重或 paper ledger。

## 已覆盖的质量边界

| 检查 | 规则 | 结果 |
|---|---|---|
| 供应商响应 | 股票快照读取嵌套 `ticker`；指数读取 `results[].ticker` | 通过 |
| 业务错误 | 指数项 `NOT_ENTITLED`/`NOT_FOUND` 映射为同名质量状态 | 通过 |
| HTTP 错误 | 401/403/404/429 不进入有效行情 | 通过 |
| JSON 解码 | 2xx 非法 JSON 或非对象响应为 `FAILED` | 通过 |
| 数值范围 | 非正价格、负成交量为 `NEEDS_REVIEW` | 通过 |
| 时间 | 未来时间、源时间回退、超过 1800 秒陈旧窗口均不发布为 `OK` | 通过 |
| 幂等 | 语义去重键不含本地抓取时间和 request id | 通过 |
| 运行时 | 服务失败进入退避，不自旋；质量失败发布 `degraded` | 通过 |

## 证据

- `tests/realtime` 局部质量/客户端/轮询/运行时测试：36 项通过。
- `tests/e2e/m16`：19 项通过，包含 provisional 边界、SSE 契约和启动链。
- M16.5 本地与 GitHub Actions Evidence 均为 18/18 门禁通过，失败 0，跳过 0。
- 真实 Massive 请求不在离线 Harness 中执行；使用正式运行时的 `MASSIVE_API_KEY` 后，供应商返回仍经过同一质量路径。

## 尚不代表的内容

受控 fixture 回放证明的是解析、质量和状态边界，不证明当前时刻 Massive 账户套餐对所有指数的授权，也不把盘中观察当作策略回测结果。真实连接出现未授权或缺失时，页面应保持不可确认状态。
