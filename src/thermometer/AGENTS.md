# AGENTS.md — 温度计领域层

## 定位

`src/thermometer/` 是未来产品的纯领域层，负责把带有时间和质量信息的指标快照转换为策略状态、证据、温度计解释和目标权重合同。它不负责抓取数据、读写数据库、渲染页面或下单。

## 真相来源

- v10 的冻结配置和策略版本合同是唯一规则来源。
- `temperature`、`trend`、`signal_agreement` 是展示模型，不得反向驱动状态机。
- 状态机只能使用 `signal_date` 当时可见的数据；执行日期必须明确晚于信号日期。
- 缺失、陈旧或待复核的数据不得产生 `CONFIRMED` 状态。

## 实现边界

- 使用纯函数、不可变输入/输出和明确的枚举；禁止在领域函数中访问网络、环境变量、数据库或 Streamlit。
- 不在这里增加未经批准的指标、资产、阈值、仓位或自动优化器。
- MA/EMA/RSI/MACD/KDJ/OBV 等指标只有在有明确经济假设、版本号、消融测试和用户批准时才能进入生产信号；“指标越多越好”不是理由。
- v10 的冲击、恢复、滞回和最短持有期必须通过代表性历史 fixture 验证，包括 2008、2019、2020 和 2022 类型阶段。
- 目标权重必须经过总和、非负/空头边界、warmup、执行日期和状态转换校验。

## 测试门槛

每个规则至少需要：手算小样本、边界条件、重复运行一致性、未来数据防护、信号/执行日错位检查和失败数据状态测试。没有测试证据就不能把领域函数接入 API 或前端。
